মূল ধারণা
🗃️

ডেটাবেস = নিয়মে বাঁধা লেজার

একই ধরনের তথ্য এক টেবিলে, প্রতিটি সারি একটা রেকর্ড, প্রতিটি কলাম একটা বৈশিষ্ট্য।

চারটা শব্দ

table, row, column, primary key

Tableএকই ধরনের ডেটাstudents, orders।
Rowএকটা রেকর্ডএকজন ছাত্র।
Columnএকটা বৈশিষ্ট্যname, city, price।
Primary keyসারির অনন্য পরিচয়id — কখনো দুইবার নয়।

এক্সেল শিট

চেনা জিনিসএক্সেল
→
টেকের নামডেটাবেস

দেখতে একই — সারি আর কলাম। কিন্তু ডেটাবেসে অনেক ইউজার একসাথে কাজ করে, নিয়ম মানায়, কোটি সারিতে দ্রুত খোঁজে, আর ভুল হলে ফিরিয়ে আনে।

টেবিল বানানো

CREATE TABLE

CREATE TABLE students (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  city TEXT,
  age INTEGER
);

PRIMARY KEY অনন্য পরিচয়, NOT NULL খালি রাখা যাবে না।

সম্পর্কের চারটা শব্দ

foreign key, one-to-many, many-to-many, normalization

Foreign keyঅন্য টেবিলের idorders.user_id → users.id।
One-to-manyএকজনের অনেকএক ইউজারের অনেক অর্ডার।
Many-to-manyঅনেকের সাথে অনেকছাত্র-কোর্স; মাঝে টেবিল।
Normalizationডেটা পুনরাবৃত্তি কমানোএক তথ্য এক জায়গায়।

🔑

Primary key কখনো বদলাবে না

নাম বদলাতে পারে, ফোন বদলাতে পারে — তাই key হিসেবে id ব্যবহার করো। Auto-increment id সবচেয়ে সহজ।

SQL বনাম NoSQL

SQL

  • টেবিল, সারি, কলাম
  • স্কিমা আগে ঠিক
  • ব্যাংক, অর্ডার, হিসাব

NoSQL

  • ডকুমেন্ট, key-value
  • স্কিমা নমনীয়
  • লগ, ক্যাটালগ, দ্রুত বদলানো

ডেটার আকার আর সম্পর্ক দেখে বাছো।

📏

Schema = ডেটার নিয়ম

স্কিমা ঠিক করে কোন কলাম আছে, কী টাইপ, কী বাধ্যতামূলক। নিয়ম থাকলে ভুল ডেটা ঢুকতে পারে না। নিয়ম বদলাতে migration দরকার।
